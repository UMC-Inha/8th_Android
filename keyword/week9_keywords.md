# Week 9 Keywords

## 서버

### 서버란?

**데이터를 저장, 관리하며 클라이언트에 서비스를 제공하는 컴퓨터 시스템**  
🔗 출처: [서버란?](https://germmen.tistory.com/entry/%EC%84%9C%EB%B2%84%EB%9E%80)

### 서버와 유사한 예시

- 레스토랑의 주방: 주문 → 요리 제공
- 도서관 자료실: 요청한 책 제공

---

## 서버와 클라이언트

### 관계

- 일반적으로 1:N 관계  
- 문장 완성: **서버는 N개의 클라이언트가 접근한다.**

### 예시 설명

- 식당: 손님(클라이언트) → 점원(요청) → 주방장/냉장고(서버) → 음식 제공

---

## 서버-클라이언트 통신

### 사전 조건

- 클라이언트는 **서버 주소와 포트**를 알아야 함

### API 문서란?

- API 서버와 소통하기 위한 정보가 담긴 문서  
- 예: API 설명서, Swagger 문서 등

---

## HTTP Protocol

### 핵심 구성요소

1. **Request**: 클라이언트 → 서버 요청 (GET, POST 등)
2. **Response**: 서버 → 클라이언트 응답 (상태코드, 데이터)

### 연결 유지 여부

- HTTP는 기본적으로 **Stateless (비연결형)**

---

## HTTP Method

1. **GET**: 조회
2. **POST**: 생성
3. **PUT**: 전체 수정/대체
4. **DELETE**: 삭제
5. **PATCH**: 부분 수정

---

## 데이터 전달 방식

- **Query Parameter**: `?key=value` 형태 (검색/필터용, 노출 위험 있음)
- **Path Variable**: URL 경로에 데이터 포함
- **Body**: 복잡한 데이터 구조 (POST, PUT, PATCH에 적합)
- **Header**: 부가정보 (토큰, 언어 등)

---

## 데이터 형식

- **JSON**: 키-값 기반 경량 텍스트, API 교환에 자주 사용
- **XML**: 계층적 마크업 언어, 사용률 감소 중

---

## HTTPS

- **HTTP의 보안 버전**, SSL/TLS 기반 암호화 사용  
- 데이터 전송 시 도청, 변조 방지

---

## API

### API란?

- **Application Programming Interface**  
- 소프트웨어 간 상호작용을 위한 메서드/함수 정의

### RESTful API란?

- REST 원칙을 따르는 API 설계 방식 (자원 기반, HTTP 메서드 사용 등)

---

## Android에서 HTTP 통신

### Retrofit2 라이브러리

- HTTP 통신을 쉽게 처리하는 Android용 라이브러리

### 구성 요소

1. **API 인터페이스**: 서버 엔드포인트 정의
2. **데이터 모델 클래스**: 요청/응답 데이터 모델 정의
3. **Retrofit 인스턴스**: 서버 URL, 컨버터 설정, 인터페이스 바인딩
